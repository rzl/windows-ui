# 流程待办与消息提醒

## 功能概述

当低代码业务模型绑定了流程定义后，业务数据提交进入审批环节时，系统会自动：

1. 在流程引擎中生成待办任务（`flow_tasks`）。
2. 向审批人发送站内消息提醒（`messages`，类型为「待办」）。
3. 通过 WebSocket 实时推送给在线的审批人。

审批人可在顶部通知中心或「我的待办」页面查看并处理任务。

## 审批人范围

流程节点的审批人可按以下方式指定：

| 类型 | 说明 |
|------|------|
| 指定用户 | 仅该用户收到待办 |
| 指定角色 | 该角色下所有启用状态的用户收到待办 |
| 指定部门 | 该部门下所有启用状态的用户收到待办 |

会签节点支持为多个审批人分别生成任务并发送消息。

## 消息内容

审批人收到的站内消息示例：

- 标题：`您有一条新的审批待办：请假申请流程`
- 内容：`节点「部门经理审批」需要您审批，请及时处理。`
- 链接：`/flow/pending`

## 处理流程

1. 审批人登录后，顶部铃铛显示未读待办数。
2. 点击铃铛 → 「待办」Tab → 点击待办项，进入「我的待办」页面。
3. 查看业务数据与流程轨迹，填写审批意见。
4. 点击「通过」或「驳回」。
5. 点击「转办」可将任务交给其他用户处理。
6. 系统将该条待办消息标为已读，并：
   - 若流程结束，向发起人发送结果通知（通过/驳回）。
   - 若还有下一审批节点，向下一审批人发送新的待办消息。

## 流程委托

若其他用户将审批任务委托给当前用户，「我的待办」列表会显示委托来源，流程轨迹中也会记录委托关系。委托仅生效于设置的有效期内。

## 发起人通知

流程审批结束后，发起人会收到一条「通知」类型的消息：

- 通过：`流程「请假申请流程」已审批通过`
- 驳回：`流程「请假申请流程」已被驳回`

## 常见问题

**Q：为什么审批人没有收到待办消息？**
A：请检查：
1. 流程定义是否已启用；
2. 当前节点是否正确配置了审批人；
3. 审批人账号是否处于启用状态；
4. 后端 WebSocket 服务是否正常运行。

**Q：角色/部门下用户很多时，消息发送会慢吗？**
A：当前版本会同步为每个用户发送消息；若角色/部门下用户数量较大，后续建议启用消息队列优化。
