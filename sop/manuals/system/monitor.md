# 系统监控

系统监控模块提供服务器运行状态、接口性能、慢 SQL、告警规则与告警记录等能力，帮助管理员及时发现并处理系统异常。

## 服务器信息

进入「系统监控」页面，顶部卡片展示当前服务器的运行信息：

- 操作系统与架构
- 主机名与 Node 版本
- 服务运行时长
- CPU 核心数
- 总内存与空闲内存
- 系统负载

## 性能概览

性能概览区域展示最近 24 小时的关键指标：

| 指标 | 说明 |
|------|------|
| API 总请求 | 最近 24 小时接收的接口请求总数 |
| 慢请求 | 响应耗时超过 1 秒的请求数量 |
| 服务端错误 | HTTP 状态码 ≥500 的请求数量 |
| 慢 SQL | 最近 24 小时采集到的慢 SQL 总数 |
| P95 耗时 | 最近 24 小时接口耗时的 95 分位数 |
| P99 耗时 | 最近 24 小时接口耗时的 99 分位数 |
| 未读告警 | 当前未读的告警记录数量 |

## 慢 SQL

系统会自动采集执行耗时超过 100ms 的 SQL。可在查询区输入 SQL 关键字或调整最小耗时阈值，点击「查询」过滤列表。

列表展示：

- SQL 文本（截取前 120 字符）
- 执行耗时
- 发生时间

## 告警规则

### 新增规则

点击「+ 新增规则」打开配置窗口：

| 配置项 | 说明 |
|--------|------|
| 规则名称 | 便于识别的规则名称 |
| 告警类型 | 接口响应慢 / SQL 执行慢 / 错误率过高 / 服务器负载高 |
| 阈值 | 触发告警的临界值（毫秒或百分比） |
| 统计窗口 | 在最近 N 分钟内进行统计 |
| 通知渠道 | 站内信 / 邮件 / 短信（当前主要记录告警记录） |
| 启用 | 是否启用该规则 |

### 规则类型说明

- **接口响应慢**：最近窗口期内存在请求耗时超过阈值的接口。
- **SQL 执行慢**：最近窗口期内存在执行耗时超过阈值的 SQL。
- **错误率过高**：最近窗口期内 5xx 错误率超过阈值百分比。
- **服务器负载高**：1 分钟平均负载占 CPU 核心数的百分比超过阈值。

### 编辑与删除

每条规则右侧提供「编辑」和「删除」按钮。删除后规则立即失效。

## 告警记录

当告警规则触发时，会自动生成告警记录。列表展示：

- 触发规则名称
- 告警类型
- 告警内容
- 处理状态（待处理 / 已解决）
- 是否已读
- 触发时间

### 处理告警

- **标为已读**：点击后该记录标记为已读，未读告警数减少。
- **解决**：点击后将该记录状态更新为「已解决」。

也可以点击「立即检查」按钮手动触发一次告警规则扫描。

## 告警实时推送

当告警规则触发时，系统会：

- 通过 WebSocket 向规则的接收人推送实时告警通知。
- 向接收人发送站内消息，顶部通知中心会显示未读角标。
- 若规则未配置接收人，则向所有在线用户广播告警。

## 数据治理

为防止监控数据无限增长，系统提供自动清理策略：

- 进入「系统监控」页面底部的「数据治理」卡片，可查看各监控表的保留策略。
- 支持调整保留天数与是否启用自动清理。
- 保留天数设置为 0 表示不自动清理。
- 后台每 6 小时自动执行一次清理。
- 点击「立即清理过期数据」可手动触发。

默认保留策略：

| 数据表 | 默认保留天数 |
|--------|--------------|
| api_metrics | 30 |
| sql_metrics | 30 |
| alert_records | 90 |
| custom_api_logs | 30 |
| operation_logs | 180 |
| data_logs | 180 |

## 注意事项

- 告警检查默认每 60 秒执行一次。
- SQL 采集阈值默认 100ms，可在后端配置中调整。
- 通知渠道当前以站内信和 WebSocket 实时推送为主，邮件 / 短信需要额外配置 SMTP / 短信服务商。
